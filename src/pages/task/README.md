# task

Страница `/tasks/:id` — решение задачи студентом. Устроена как вкладка «Как увидит студент» в конструкторе, только задача приходит с бэка, а проверка настоящая.

## Как устроена

- Задача загружается запросом `getTask` (`api/getTask.ts`). Граф в нём приходит только ссылкой: есть `id`, а вершин и рёбер нет. Тогда (`graphToLoad`) граф догружается отдельно запросом `getGraphById` (`api/getGraph.ts`), как делал старый фронт. `toTaskView` переводит её в удобный вид: граф через `fromBackendGraph`, правила `rule` → правила редактора (`rulesFromBackend`, `isEdit` включает и добавление, и подписи), условия → список «Что проверяется».
- Слева условие: категория, название, автор, описание, подсказки (`taskHints`), «Граф задачи» только для просмотра (`GraphCanvas readonly`) и «Что проверяется».
- Справа «Ваш ответ» — редактор с правилами задачи. С чего начинается ответ, решает то же правило, что и в конструкторе (`answerStartsFromTask`): если граф задан и добавлять нельзя — копия графа задачи, иначе пустое поле того же вида, что граф задачи. Для пустого поля есть галочка «Ориентированный граф», потому что вида графа у задачи на бэке пока нет. «Начать заново» возвращает ответ к началу.
- «Проверить решение» отправляет `solveTaskGraph` (`api/solveTask.ts`) с ответом через `toGraphInput`. Id решения и графа придумывает фронт (`createId`): бэк сам их не создаёт и без них падает с `UNKNOWN`, так же делал старый фронт. Результат (`toCheckResult`): «Верно!» или список непройденных проверок. Текст ошибки берётся у автора задачи (`mistakeText` условия), если его нет — `pluginMessage` от бэка, если нет и его — «Не выполнено: <плагин>». Для чисел и строк ниже пишется, что получилось у студента. Если у задачи `isHiddenMistake`, показывается только первая ошибка.
- Как только ответ меняется, результат прошлой проверки пропадает.
- Ошибки: задачи нет (`NOT_FOUND`) — ссылка к списку, остальное — «Повторить». Задачи на написание кода (`TaskImplementation`) пока не открываются.

## Файлы

- `api/getTask.ts`, `api/solveTask.ts` — запрос задачи и мутация проверки;
- `model/taskView.ts` — задача с бэка для страницы: `toTaskView`, `rulesFromBackend`, `checkText`, `answerStartsFromTask`, `startAnswer`, `canPickDirection`, `taskHints`;
- `model/checkResult.ts` — ответ проверки для студента: `toCheckResult`, `mistakeText`, `mistakeDetail`;
- `model/errors.ts` — тексты ошибок загрузки и проверки;
- `model/useTask.ts`, `model/useSolve.ts` — загрузка задачи и отправка решения;
- `ui/TaskPage.vue` — сама страница.

## Что дальше

- `pluginsInput` в решении не отправляется: для плагинов `GRAPH_STRING` студент, видимо, должен вводить строку. Нужно уточнить у Вадима, как это устроено;
- правила ответа и вид графа частично повторяют конструктор (`rulesFromBackend` ≈ `rulesFromInput`, `answerStartsFromTask`). Когда страницы устоятся, общее стоит вынести в виджет;
- статистика задачи (`getStatistic`): отправки, решили верно, успешность — как в макете;
- вид графа и «с чего начинается ответ», когда эти поля появятся на бэке.
